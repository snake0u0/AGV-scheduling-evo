**이 기간에 일어난 가장 중요한 일은 두 가지다.**

1. **막혀 있던 데이터셋 하나를 열었고, 시뮬레이터가 문헌 해를 10/10 정확히 재현했다.**

2. **프로젝트의 핵심 주장 - "LLM이 진화시킨 AGV 규칙이 문헌 규칙을 이긴다" - 이 무너졌다.**

## 1. 문제 설계 - 우리가 푸는 문제

### 대상 문제

**FJSP-AGV** (Flexible Job Shop Scheduling with AGV transport).
작업(job)들이 여러 공정(operation)을 순서대로 거치는데,

- 각 공정은 **여러 기계 중 하나**에서 처리 가능하고 (= flexible)
- 공정 간 이동은 **유한한 수의 AGV**가 운반해야 한다 (= transport)

목적은 **makespan**(전체 완료시각) 최소화다. 단일 목적이다.

### 하위문제 4개

| # | 결정 | 언제 발화하나 |
|---|---|---|
| 1 | machine selection - 이 공정을 어느 기계에 | 공정이 준비됐을 때 |
| 2 | operation sequencing - 이 기계에 몰린 공정 중 무엇 먼저 | 기계가 비었을 때 |
| 3 | AGV selection - 이 운반을 어느 AGV가 | 운반이 준비됐을 때 |
| 4 | AGV sequencing - 이 AGV가 대기 운반 중 무엇 먼저 | AGV가 비었을 때 |

**자원 2종(기계/AGV) x 이벤트 2종(자원이 빔/작업이 준비됨)의 2x2 구조다.**
대충 구현하면 1과 2가, 3과 4가 각각 하나로 붕괴한다.

### 문헌의 빈칸 (우리 자리)

- **메타휴리스틱 계열**(Han 2024 DCGA, Meng 2025 DCGA-CP, Homayouni BRKGA)은
  **1·2번만 진화**시키고 3·4번은 **고정 디코딩 규칙**에 위임한다.
  Han은 Decoding1/Decoding2 중 우열을 못 가려 이중 population으로 회피한다.
- **RL/NCO 계열**은 사람이 만든 규칙 풀에서 고르거나 가중치만 조정한다.
- 즉 **4개를 함께, 해석 가능한 형태로 자동 설계한 사례가 없다.**

### 타깃

KIIE 학술대회 → SCIE 저널. 경쟁 위협 1순위는 HUST(Gao Liang / Li Xinyu) 그룹.

## 2. 방법론 설계 - 2026-07-31 회의에서 확정한 것

이전 설계는 "GA가 OS/MS를 탐색하고, LLM이 AGV 규칙 1개를 진화"였다.
즉 **하위문제 4개 중 실제 진화 대상은 1개**(3번)뿐이었고, 4번은 결정 자체가 없었다.

바꾼 내용은 다음과 같다. 각 항목의 근거는 3절 실험들이다.

| 항목 | 결정 | 이유 |
|---|---|---|
| **구조** | **슬롯 5개 고정 스키마** (하위문제 4개 + LNS destroy). 개체 하나가 5칸을 다 들고 있고, 적합도도 하나 | 4개를 "같이" 진화시키려면 조합 전체에 선택압이 걸려야 함. 슬롯이 고정이라 **슬롯 되돌리기 = 즉석 ablation** |
| **solver** | GA → **LNS** | Berterottière 2026 결론이 LNS와 reconstruction 연산자를 지목. VRPAgent가 VRP에서 같은 패러다임으로 SOTA 갱신 |
| **프롬프트** | EoH(슬롯별 생각 + 개체당 design_rationale) + ReEvo(슬롯 귀속 강제 반성 + 누적 설계원칙) | 두 논문 모두 개체가 함수 1개일 때를 전제 - 5슬롯에는 "어느 슬롯 얘기냐"가 빠져 있어 보강 |
| **목적** | **makespan 단일** | 사용자 결정. TTT는 비용 0이라 보조 기록만 |
| **openevolve** | 코드베이스 채택 안 함, **캐스케이드 평가만 이식** | claude CLI 백엔드 불일치. EoH/ReEvo와 AlphaEvolve는 보완재가 아니라 경쟁 프레임워크 |
| **검증 반성층** | **제외** | 방법론적으로 가장 차별적이나 없어도 논문이 섬. 일정 위험 회피 |

**성능 주장의 위치 (중요)**: makespan SOTA(DCGA-CP)를 이긴다고 주장하지 않는다.
상대는 CPLEX로 최적성을 증명한 결과다. 주장은 "해석 가능한 5슬롯 결합 규칙을 LLM이
자동 설계했고, 문헌 고정 규칙과 손규칙을 이기며, SOTA 대비 격차와 계산시간의
트레이드오프가 이렇다"이다.

**근거 문헌 2편** (이번에 확인)

- **Berterottière et al. (2026) EJOR 332:322-335** - FJSPT의 makespan+TTT tabu.
  결론에서 *"metaheuristics based on large neighborhoods... particular attention should be
  paid to the reconstruction operator"*라고 다음 수순을 직접 지목.
- **VRPAgent (arXiv:2510.07073)** - 저장소 코드 확인 결과 진화 슬롯이 정확히 2개:
  `select_by_llm_1`(LNS destroy) + `sort_by_llm_1`(repair 순서). **우리 옵션 D와 같은 패러다임**이고
  CPU 코어 1개로 VRP SOTA를 갱신했다. `novelty_sweep.md`에 "LLM 연산자+GA"로 적혀 있던 한 줄은
  부정확했고 정정했다. 카드 = `docs/research/cards/vrpagent.md`.

### 3.1 폴더 개편 + Deroussi 데이터셋 개방 (07-31)

**왜**: 폴더명(`sim/` `ahd/` `fjspt/`)이 직관적이지 않았고,
데이터셋 4계열 중 이동시간 행렬이 있는 게 1계열(Dauzere)뿐이라 "5개 데이터셋 전부"가 불가능했다.

**했다**: 역할 기준 개편(`simulator/` `model/` `experiments/` `data/` `docs/` `archive/`).
그리고 Han 2024가 본문에 적어둔 데이터셋 페이지에서 Deroussi&Norre 배포 PDF를 받았다.

**나왔다**:
- **replay 검증 10/10.** fjsp1~10 전부 공표 makespan을 정확히 재현. 한 달 넘게
  "이 데이터셋에서는 불가능"으로 STATUS에 박혀 있던 항목이다.
- **막혔던 원인은 시뮬레이터가 아니라 전제 오류였다.** 이 인스턴스는 4기계가 아니라

  그래서 기존 재구성 가설 8종이 전부 실패할 수밖에 없었다.
- 사용 가능 벤치마크 54 → **64 케이스**.

**교훈**: 행렬을 추측하는 데 쓴 시간보다 원출처 페이지를 여는 데 든 시간이 훨씬 적었다.

### 3.2 예산 vs 구조 게이트 (07-31) - **결론이 나중에 뒤집힘**

**왜**: 2026-07-29에 문헌 대비 격차 65%를 측정했는데, 그게 예산 부족인지 알고리즘 구조 문제인지
구분된 적이 없었다. LNS는 2~3주짜리 구현이라 근거가 필요했다.

**했다**: 규칙 5개 x 예산(10/60/600초) x 시드 3개 x 케이스 8개 = 360 runs.

**나왔다**: 평가 61배(3.8만→233만)에 격차 12%p 감소(76.1%→64.1%).
"예산으로는 안 닫힌다, 구조 문제다" → **LNS 승인**.

**그런데 이 결론은 틀렸다.** 이 실험은 전부 population 70에서 돌렸다.

### 3.3 GA 진단 (07-31b) - 결론을 뒤집음

**왜**: "LNS가 GA를 이겼다"고 할 때 그 GA가 **정당한 대조군인지** 확인하지 않았다.
조기 수렴이었다면 처방이 완전히 달라진다.

**했다**: 시간(600초)과 평가 횟수(약 148만회)를 **똑같이 고정**하고 설정만 바꿈.
pop70 / pop300 / pop1000 / 재시작(60초x10회) / 탐욕 MS 초기화. 75 runs.

**나왔다**:
- **population만 70→1000으로 바꾸니 Dauzere 격차 94.5% → 24.1%** (18a는 140.4% → 34.4%).
  4 인스턴스 x 3 시드 **12/12 전부 개선**, pop1000의 최악값이 pop70의 최선값보다 좋다.
- **조기 수렴이 아니었다.** pop70의 마지막 개선 시점이 전체 세대의 0.83~0.87 - 끝까지 개선 중이었다.
  재시작도 거의 무효(87.8%). 원인은 **유전자 풀 부족**: 공정 387개 x 대안기계 5개 공간에
  개체 70개가 담은 재료로는 균등교차가 재조합할 게 없다.
- **탐욕 MS 초기화(처리시간 최소 기계 80% 편향)는 오히려 악화**(94.5% → 102.0%).
  → 기계 선택은 처리시간만의 문제가 아니다. 빠른 기계가 멀리 있을 수 있고 경합이 생긴다.
  **단일 특징 손휴리스틱이 무작위보다 나쁘다**는 것은 이동·부하를 결합하는 규칙이
  필요하다는 직접 근거다.

보고서 `2026-07-31b-ga-diagnosis-population-not-structure.md`

### 3.4 GA 튜닝 (08-01)

**왜**: 3.3에서 population과 엘리트 비율이 **같이** 바뀌었다(`n_elite=10` 고정이라
pop70에서 14.3%, pop1000에서 1.0%). 진짜 원인이 선택압일 수 있었다.
그리고 pop1000이 아직 예산 제약 상태(마지막 개선 0.92~0.98)라 상한을 몰랐다.

**했다**: 교차 대조 설정 2종(`pop70_elite1`, `pop1000_elite143`) + pop3000/pop10000 +
변이율 상향. 두 예산(10초/600초). 168 runs.

**나왔다**:
- **엘리트 교란 기각.** pop1000에서 엘리트를 1.0%→14.3%로 올려도 24.0%→23.9%(무변화).
  pop70에서만 크다(94.5%→61.9%). **엘리트는 population 부족의 증폭기이지 원인이 아니다.**
- **population은 U자다.** 600초에서 70=94.5% / 300=37.5% / **1000=24.0%** / 3000=92.8% / 10000=144.9%.
  평가 횟수는 전부 38~43만회로 같다 → **일의 양이 아니라 배분 문제.**
  세대 수 6668/1470/427/129/37. pop10000은 37세대뿐이라 진화가 성립하지 않는다.
- **최적 population은 예산에 따라 이동한다.** 10초→pop70, 600초→pop1000.
- **핵심**: 예산맞춤 시 10초 111.9% → 600초 **23.9%**(88.1%p 감소). pop70 고정은 17.9%p.
  → **3.2의 "예산으로 안 닫힌다"는 완전 기각.** 예산이 커질수록 점점 더 틀린 population을
  고정해 놓고 잰 결과였다.

보고서 `2026-08-01-ga-tuning-population-generations-tradeoff.md`

### 3.5 규칙 우위 재검정 (08-01b) - **핵심 주장이 무너진 지점**

**왜**: 지금까지 **모든 캠페인이 pop=70**이었다. pop70은 600초에서 최적의 4배 나쁜 설정으로
드러났으므로, 그 위에서 잰 규칙 비교가 유효한지 확인해야 했다.

**했다**: D1/D2/P_main/P2/P3 + 2x2 ablation 4셀을 600초 x pop1000에서 재측정.
8케이스 x 3시드 = 24쌍. 216 runs.

**나왔다**:

| 규칙 | pop70 격차 | pop1000 격차 | D1 대비(pop70) | D1 대비(pop1000) |
|---|---|---|---|---|
| **D2 (문헌)** | 65.73% | **16.28%** | -0.38p | **+0.46p** |
| D1 (문헌) | 65.35% | 16.73% | 0.00p | 0.00p |
| P_main | 62.00% | 16.75% | **+3.35p** | -0.02p |
| P2 | 60.69% | 17.00% | **+4.66p** | -0.26p |
| P3 | 66.70% | 17.72% | -1.35p | -0.99p |

- **순위가 통째로 뒤집혔다. 문헌 규칙이 1·2위.**
  짝지은 Wilcoxon 6조합 **전부 유의하지 않다**(p=0.40~0.79).
- **2x2 ablation도 무너졌다.** 공차 주효과가 p=0.0001 → **1.27%p, p=0.063**(방향만 잔존, 24쌍 중 16승).
  **상호작용은 0.02%p로 소멸**(pop70에선 p=0.018).
- 규칙 간 폭(1.1~4.2%p)이 시드 노이즈(0.7~2.9%p)와 같은 자릿수다.
- **기제**: 강한 메타휴리스틱이 부품 휴리스틱의 기여를 흡수한다.
  pop1000 x 427세대 GA는 AGV 규칙이 나빠도 OS/MS로 보상한다.

보고서 `2026-08-01b-rule-advantage-does-not-survive-a-tuned-solver.md`
무효화 주석을 캠페인 보고서 3편에 부착했다.

### 3.6 규칙 x 예산 x population 전수 (08-06)

**왜**: 3.5가 남긴 희망 중 하나가 "저예산에서는 규칙이 중요할 것"이었다.
성립하면 논문의 링이 동적/온라인 쪽으로 이동한다.

**했다**: 규칙 5개 x 예산 4종(1/10/60/600초) x 예산별 population 후보 3종 x 4케이스 x 3시드.
660 runs. population을 예산마다 같이 탐색해야 "예산 효과"와 "설정이 틀림"이 안 섞인다.

**나왔다**:
- **population 스케일링 법칙 확보**: `pop ≈ 20 x (예산초)^0.6`.
  실측 최적 20/70/300/1000 vs 예측 20/80/233/929. 네 점 전부 일치.
- **"저예산에서 규칙이 중요"는 기각.** 규칙폭/시드노이즈 비율이 비단조(1.6/0.6/3.0/0.8배)이고,
  **규칙이 가장 중요한 60초에서 문헌 D1/D2가 1·2위이며 6쌍 전부 p<0.025로 진화 규칙이 진다.**
- **진짜 원인: 훈련 체제 과적합.**

  | 예산 | 평가 횟수 | 진화 − 문헌 (4케이스) | 판정 |
  |---|---|---|---|
  | 1초 | 677 | −3.2 / −12.5 / −3.5 / −1.5 | 4/4 진화 승 |
  | 10초 | 6,950 | −1.2 / −7.5 / −1.2 / +9.6 | 3/4 진화 승 |
  | 60초 | 42,016 | −1.4 / +4.2 / +12.0 / +15.2 | 3/4 문헌 승, 크게 |
  | 600초 | 456,697 | +3.1 / +0.6 / +0.8 / −2.9 | 무승부 |

  **이 규칙들이 진화된 체제 = GA 70x70 = 약 4,900회 평가.** 그 값이 677회와 6,950회 사이에
  정확히 놓이고, 진화 규칙이 이기는 구간이 바로 거기다.
  → **진화가 찾은 것은 "좋은 AGV 규칙"이 아니라 "약한 GA의 약점을 보완하는 규칙"이었다.**
- 유의하게 이긴 조합은 전체에서 **1초의 P2 vs D2 하나뿐**(10/12, p=0.016).
- 튜닝 예산 곡선 158.7% → 115.5% → 74.0% → **24.3%**, **평평해질 기미 없음**.

## 7. 무엇을 해야 하나

### 즉시 (Stage 1)

**이벤트 구동 평가기 + 4슬롯 분리.** `simulator/agv_fms.py`의 이벤트 루프와
`simulator/timing.py`의 정확한 타이밍을 합친다.

- 완료 판정: **손규칙 조합(SPT+D1)이 현행 `decode()`의 D1과 같은 Cmax를 내는 동치성 회귀 테스트**
- 부수 소득: **순수 구성형(탐색 0회) 기준선을 처음으로 측정 가능**해진다.
  지금까지 이 값을 모른다(1초 예산조차 pop20에서 66세대를 돈다).

**왜 지금인가**: 규칙 단독으로 정적 링에서 못 이긴다는 것이 3.5와 3.6에서 두 번 확인됐다.
슬롯 1·2·4와 destroy를 실제로 만들어야 더 나아간다.

### 그다음 (Stage 2~3)

- **Stage 2**: LNS 뼈대 + 손규칙 destroy/repair. 판정 = 같은 시간예산에서 튜닝된 GA를 이긴다.
  **destroy는 반드시 기계 재배정을 유발해야 한다**(순서만 흔들면 병목을 못 건드림).
- **Stage 3**: 5슬롯 진화 루프. **배포 체제를 적합도로 쓴다.**

### 미해결 설계 충돌 (Stage 3 전에 풀어야 함)

**"적합도 체제 = 배포 체제"(2026-08-06 측정)와 "캐스케이드 저예산 1단계"(비용 절감)가
정면으로 충돌한다.**

- 배포가 600초 x pop1000이면 적합도 1회에 600초. 후보 200개면 6케이스 x 3시드 x 200 = 60만초.
- 캐스케이드로 1단계를 10초로 낮추면, 그 10초 체제에 과적합된 규칙이 살아남는다.
  그게 바로 이번에 실패한 방식이다.

가능한 방향(미결정): (a) 1단계를 저예산이되 **순위 상관이 검증된 구간**으로 제한,
(b) 1단계를 배포 체제로 하되 케이스 수를 줄임, (c) 배포 체제 자체를 낮춤.
**어느 쪽이든 결정 전에 근거 측정이 필요하다.**

### 우선순위가 내려간 것

- **예산 곡선 3600초 연장 → LNS 판정**: 튜닝 곡선이 평평해질 기미가 없어서
  "GA로 충분하다" 쪽으로 기울고 있다. 다만 LNS의 진짜 근거는 이제 성능이 아니라
  **"destroy가 진화 슬롯이 된다"**는 구조적 이유다.
- fattahi / Homayouni_Brandimarte / Kumar EX-series 데이터 개방:
  이동시간 출처 미확인. Stage 5(최종 SOTA 비교) 전까지 필요.

## 9. 실무 규칙 (앞으로 모든 실험에 적용)

1. **population은 `20 x (예산초)^0.6`으로 정한다.** 임의 고정 금지.
2. **진화의 적합도 체제 = 배포 체제.** 다른 체제 규칙은 전이되지 않는다.
3. **규칙 비교는 예산과 population을 둘 다 명시한다.** 한쪽만 밝히면 재현 불가.
4. **시드 (0, 21, 42) 고정, 모든 설정에 동일 적용** = 짝지은 비교.
5. **새 방법이 기존 방법을 이겼다고 말하기 전에, 기존 방법이 정당하게 설정됐는지 먼저 확인한다.**
   이번에 이 질문 하나가 잘못된 전제 위의 2~3주짜리 구현을 막았다.
