# Han et al. (2024) DCGA — 문제 정식화 · 디코딩 정리 (우리말)

출처: `docs/data/papers/Han2024_SwarmEvolComput_DCGA.pdf`
용도: (1) 변수·제약 이해, (2) evaluator(스케줄→makespan) 설계도
주의: 논문을 읽으며 대조 확인할 것. 특히 제약식의 정확한 형태는 원문 (1)~(16)을 볼 것.

---

## 1. 가정 (Section 3.1)

1. 초기 상태: 모든 기계·AGV가 시각 0에 사용 가능, 모든 작업도 시각 0에 처리 가능 (정적)
2. 기계 점유: 한 기계는 동시에 한 공정만 처리
3. AGV 점유: 한 AGV는 동시에 한 작업만 운반 (적재량 1)
4. 공정 처리: 각 공정은 기계 하나에서 처리되고 AGV 하나가 운반. 같은 작업의 공정들은 정해진 순서를 따르고, 다른 작업의 공정끼리는 순서 제약 없음
5. 연속 처리: 한번 시작한 공정은 중단 불가 (non-preemptive)
6. 기타: 같은 기계에서 작업이 바뀔 때의 셋업 시간은 무시

## 2. 파라미터 (Table 1)

| 기호 | 뜻 |
|---|---|
| `i, i'` | 작업(job) 인덱스 |
| `n` | 작업 수 |
| `I` | 작업 집합 = {1,...,n} |
| `j, j'` | 공정(operation) 인덱스 |
| `n_i` | 작업 i의 공정 수 |
| `J_i` | 작업 i의 공정 집합 = {1,...,n_i} |
| `J0_i` | = {0,1,...,n_i}. **공정 0은 가상 공정**(작업의 출발을 나타냄, 처리시간 0) |
| `O_ij` | 작업 i의 j번째 공정 |
| `m` | 기계 수 |
| `K` | 기계 집합 = {0,1,...,m}. **기계 0 = 출발 위치 LU** |
| `K_ij` | 공정 O_ij를 처리할 수 있는 기계 집합 (= 유연성) |
| `m_ij` | O_ij의 선택 가능 기계 수 |
| `nA` | AGV 수 |
| `V` | AGV 집합 = {1,...,nA} |
| `pt_ij,k` | 공정 O_ij를 기계 k에서 처리하는 데 걸리는 시간 |
| `Tr_k,k'` | 기계 k에서 k'까지의 운반시간. **`Tr_0,k` = LU에서 기계 k까지** |

메모: 가상 공정 0과 기계 0(LU)을 두는 이유 = "작업이 LU에서 첫 기계로 이동하는 것"도 일반 운반과 똑같이 다루기 위함. 코드에서도 이렇게 하면 예외 처리가 줄어듦.

## 3. 결정변수 (Table 2)

| 기호 | 종류 | 뜻 |
|---|---|---|
| `X_ijkv` | 0-1 | 공정 O_ij를 **기계 k에서 처리하고 AGV v가 운반**하면 1 |
| `YM_iji'j'` | 0-1 | 같은 기계에서 O_ij가 O_i'j'보다 **먼저 처리**되면 1 |
| `YA_iji'j'` | 0-1 | 같은 AGV가 O_ij를 O_i'j'보다 **먼저 운반**하면 1 |
| `S_ij` | 연속 | 공정 O_ij의 **시작 시각** |
| `SA_ijv` | 연속 | AGV v가 O_ij를 목적 기계로 운반해 **도착한 시각** |
| `C_max` | 연속 | **makespan** (최대 완료 시각) |

우리 4가지 결정과의 대응:
- 기계 배정 → `X`의 k 부분
- AGV 배정 → `X`의 v 부분
- 기계별 처리 순서 → `YM`
- AGV별 운반 순서 → `YA`

즉 Han은 X 하나에 기계+AGV 선택을 함께 담고, 순서는 YM/YA로 따로 둡니다.

## 4. 제약식 (1)~(16) 의미

| 식 | 의미 |
|---|---|
| (1) | 각 공정은 **정확히 하나의 (기계, AGV) 조합**에 배정 |
| (2) | 공정은 **운반이 도착한 뒤에야** 시작 가능 (S_ij ≥ 도착시각) |
| (3) | 다음 공정으로의 운반은 **이전 공정 완료 + 기계 간 운반시간** 이후에 도착 가능 |
| (4) | 작업의 출발점은 LU (가상 공정 0) |
| (5) | 첫 공정은 **LU에서 선택된 기계까지의 운반시간** 이상 소요 |
| (6) | **makespan 정의**: 각 작업 마지막 공정의 완료시각 ≤ C_max |
| (7)(8) | **기계 순서 제약**: 같은 기계에 배정된 두 공정은 겹칠 수 없음 (YM으로 순서 결정, big-M 방식) |
| (9)(10) | **AGV 순서 제약**: 같은 AGV가 맡은 두 운반은 겹칠 수 없음 (YA로 순서 결정) |
| (11)~(13) | 시간 변수의 범위(비음수 등) |
| (14)~(16) | 0-1 변수 정의역 |

핵심 구조: (7)(8)과 (9)(10)이 **분리 제약(disjunctive)** 입니다. "둘 중 하나가 먼저"를 0-1 변수 + big-M으로 표현하는 스케줄링의 전형적 패턴입니다.

## 5. 인코딩 (Section 4.2)

2계층 문자열, 두 문자열 모두 길이 = 전체 공정 수

- **OS (Operation Sequence)**: 예 `[3 2 3 1 4 2 3 1 1 4]`
  - 숫자는 작업 번호. **k번째로 나온 작업 j = 작업 j의 k번째 공정**
  - 위 예: 첫 3 = O31, 두번째 3 = O32, 세번째 3 = O33 ...
- **MS (Machine Selection)**: 예 `[2 2 2 2 3 1 1 3 1 1]`
  - 각 공정이 **선택가능 기계 집합에서 몇 번째 기계**를 쓰는지 (인덱스)
  - 예: O11이 M2, M3에서 가능한데 MS 값이 2 → 두 번째인 M3 선택

## 6. 디코딩 = evaluator 알고리즘 (Section 4.3) ★

이 부분이 우리가 만들 evaluator의 설계도입니다.

기본 절차:
1. MS 문자열로 각 공정의 **기계 결정**
2. OS 문자열로 각 기계의 **처리 순서 결정**
3. 각 공정에 대해 **AGV 선택**: "그 공정을 목적 기계로 **가장 일찍 운반할 수 있는 AGV**"를 선택
4. 시간 계산해서 makespan 산출

**AGV 선택 규칙 2종 (동점일 때만 다름)**

여러 AGV가 같은 시각에 도착 가능할 때 누구를 고르는가:
- **Decoding1**: 고정된 AGV 선택 (예: 번호가 작은 쪽)
- **Decoding2**: **누적 운반시간(공차+적재 포함)이 최소인 AGV** 선택

**어느 쪽도 항상 우월하지 않음** (논문의 핵심 관찰):
- 예제 1 (MFJS04, Fig 5·6): Decoding1 → 1152, Decoding2 → **1144** (Decoding2 승)
- 예제 2 (Fig 7·8): Decoding1 → **1643**, Decoding2 → 1688 (Decoding1 승)

→ 그래서 Han은 두 디코딩을 각각 쓰는 **두 개의 집단(dual population)** 을 운영하고 서로 협업시킵니다. 이게 논문 제목의 "dual population collaborative"입니다.

## 7. 우리 프로젝트 관점 메모

- evaluator 구현 시 위 디코딩 절차를 그대로 따르면 됨. 입력 = (MS, OS) + 인스턴스 + 이동시간 행렬, 출력 = makespan.
- 검증: `docs/data/instances/fjspt-lucasberter/DeroussiNorre/fjsp1.txt`에서 문헌 최적값 134가 나오는지 확인.
- **주의**: 이동시간 행렬이 비대칭이므로 `Tr[k][k']`의 순서를 뒤집지 말 것 (행=출발, 열=도착).
- Han은 subproblem을 3개(기계선택·AGV선택·공정순서)로 봄. Meng 2025은 AGV 운반순서를 분리해 4개. 우리 DRAFT는 4개(최신) 기준.
- **LLM이 진화시킬 후보로서의 함의**: Decoding1/Decoding2처럼 "AGV 선택 규칙"이 성능을 가르는데 어느 것도 항상 우월하지 않다는 건, 바로 이 지점이 **LLM이 더 나은 규칙을 발견할 여지가 있는 곳**이라는 뜻. 우리 방법의 진입점으로 유력함.
